# 版本与实验管理

版本：R2，2026-08-27

## 1. 分支职责

- `main`：只保存经过复核的当前最高总分方案，必须始终可测试、可打包。
- `codex/<topic>-v<number>`：所有新算法、新模块、评分策略和可能改变模型行为的尝试。开始工作后应尽早推送远端。
- `codex/<topic>`：不对应模型版本的修复、工具、治理与纯文档工作。

一个功能或假设对应一个分支，不在同一分支混入无关试验。分支从最新 `main` 创建，禁止在 `main` 直接进行高风险探索。

## 2. 方案版本

- 算法版本使用递增编号 `V<number>`，当前冠军为 `V190`。
- Git 发布标签使用 `solution-v<number>-score-<primary_score>`，例如 `solution-v115-score-62.680540`。
- 文档中的版本必须对应 `configs/final.yaml`、`modelSubmit/` 和 `benchmarks/leaderboard.json` 的同一组内容。
- 不使用“最终版”“最终最终版”等不可排序名称；未晋级候选使用分支名和实验 ID 标识。

## 3. 生成文件

| 类型 | 位置 | Git 策略 |
|---|---|---|
| 当前冠军代码与权重 | `modelSubmit/` | 跟踪；权重使用 Git LFS |
| 官方样例代码 | `ziliao/*.py` | 跟踪 |
| 训练数据、官方 baseline 权重 | `ziliao/data_train/`、`ziliao/modelSubmit/` | 忽略 |
| 候选模型、评测日志、ZIP | `artifacts/` | 忽略 |
| 训练检查点 | `checkpoints/` | 忽略 |
| 训练过程输出 | `runs/` | 忽略 |
| 可复核成绩摘要 | `benchmarks/leaderboard.json` | 跟踪 |
| 设计、研究与提交说明 | `docs/` | 跟踪 |

临时产物不能因为“以后可能有用”直接提交。需要保留时，提取必要的配置、指标、哈希和结论进入 `benchmarks/` 或 `docs/`。

## 4. 统一评测协议

主评测使用官方兼容的 batch-size-one evaluator：

- 数据切分：deterministic held-out split；
- 样本数：每个 seed 2,000 个信道样本、4,000 个 UE 分数；
- seeds：1176、1177、1178；
- 指标：efficiency mean、fairness P10、`0.7 * mean + 0.3 * P10`；
- 同一候选和冠军必须使用同一代码、数据、seed 和设备口径配对比较。

单次 smoke test 只能筛除明显退化，不能作为晋级依据。线上排行榜分数与本地分数分字段记录，不混用。

## 5. 晋级 main 的门槛

候选合并到 `main` 前必须同时满足：

1. `pytest` 和 Ruff 全部通过；
2. 三个固定 seed 的平均 final 高于当前冠军；
3. 每个 seed 都没有无法解释的显著退化；
4. 记录 efficiency、P10、final、运行时间、模型哈希和提交 ZIP 哈希；
5. 从干净的 `modelSubmit/` 成功生成官方目录结构 ZIP；
6. 更新 `configs/final.yaml`、方案文档、提交说明和 `benchmarks/leaderboard.json`；
7. 分支已推送远端，提交历史能说明假设、改动和评测结果。

若线上同版本有可信成绩，线上成绩优先作为最终判断；本地评测仍用于回归和消融。

## 6. 推荐工作流

```powershell
git switch main
git pull --ff-only
git switch -c codex/weak-user-control-semantics-vXXX
git push -u origin codex/weak-user-control-semantics-vXXX

# 实现、测试、固定 seed 评测、记录结果

git add <scoped-files>
git commit -m "feat: protect weak-user tail with control semantics"
git push
```

只有通过晋级门槛后才合并回 `main` 并创建 solution tag。失败实验保留远端分支与简短结论，但不替换主干冠军。

## 7. 消融与组合实验

- 每个候选必须以当前冠军为对照，只改变一个可命名因子；开始前使用 `docs/experiments/ablation-template.md` 预注册假设、参数、SNR 作用域、seed 和门禁。
- 一次同时改变两个因子时必须执行 C/A/B/AB 四组，不允许只比较 C 与 AB。交互项定义为 `AB - A - B + C`。
- 历史候选的局部增益不能直接相加。组合必须在相同信道、随机流和输出评分口径上重新运行。
- 参数搜索使用 discovery seed；代码与参数冻结后才可运行 blind seed。已经查看结果的 seed 永久降级为 discovery/audit，不能再次声称为盲测。
- 失败实验必须登记到 `docs/experiments/ablation-registry.md`，至少记录因子族、唯一改动、失败阶段、P10 风险和是否允许进入组合池。
- 只有单因子或组合候选均通过预注册门禁，才允许晋级 `main`。不得为了挽救盲测失败而在同一版本内修改边界。
