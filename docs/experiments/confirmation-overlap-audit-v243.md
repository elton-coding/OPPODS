# V243：确认窗口历史交叉审计（评测工具，无新模型）

## 目的与方法

V240/V242长训练仍在向69推进。为避免将后续test窗口错误称为全项目独立盲测，先在不运行模型、不读取分数值的情况下扫描现存benchmarks与artifacts内所有NPZ的data_index，以及split_seed/noise_seed/test_offset元数据。只按通道ID计算交集，双UE及重复噪声去重。脚本scripts/audit_confirmation_overlap.py；快照benchmarks/confirmation_channel_inventory_20260909_0925.json。V243是评测审计版本，不是得分方案。

声明数据规模100000，与现有H_train和训练协议一致；固定split1176为80000训练、10000validation、10000test。工具只接收此总量，不读取信道数组，也没有改变任何在训依赖。若用于其他数据版本，必须先核实总量和样本顺序，不能照搬此结论。

## 实测交叉

扫描1590个NPZ，1566个具有通道ID，24个缺少ID，无无法读取文件。具有ID记录的通道并集89841；这是历次评测记录并集，不是当前训练集大小。

|---|---:|---:|---:|---:|---:|---:|
| offset4000 | 2000 | 0 | 0 | 0 | 1779 | 0 |
| offset6000 | 2000 | 0 | 0 | 0 | 1792 | 0 |
| offset8000 | 2000 | 0 | 0 | 0 | 1812 | 0 |

显式split1176仅指NPZ元数据筛选，不等价于“纯神经所有历史”，也不等价于某个日期以后。旧版本没有显式split_seed时会随噪声seed重新划分通道，已有记录足以证明后续三个窗口大部分信道被历史评测覆盖。

固定test中只有617个通道未出现在所有已记录ID内；这不证明它们从未被评测，因为还有24个缺失ID归档以及可能缺失的日志。工具因此无条件输出blindness_certified=false，不能仅因交集0自动发放盲测证明。

## 尚未解决的证据边界

24个缺少ID的归档包括早期amplitude/analytic/identity/phase诊断、prefix_scores，以及V192/V194/V204/V210的prefix缓存。完整路径在快照中。仅根据文件名中的seed推断通道不足以证明实际运行参数，需要执行命令、生成器版本及对应索引证据；本次不进行无证据补填。父模型梯度训练的完整谱系也不是这个索引扫描工具能够证明的，当前两条纯神经训练入口代码固定split1176只能证明其自身切分规则。

确认要求应区分：

- 与当前梯度训练和validation无交叉：上述三个窗口在固定split1176规则下成立，但仍需核对候选完整训练谱系。
- 与本轮offset2000选型不重叠：成立，且未为本次审计运行任何模型评分。
- 在整个项目历史里从未评测：上述窗口明确不成立；617个未记录通道也尚未获证。
- 线上达到69：本地任何检查均不能代替实际提交成绩。

## 后续执行约束

训练继续正常进行，不因这次口径审计中断。候选达到69附近时先冻结四文件哈希和检查点，先核对谱系与剩余缺失记录，再登记确认窗口、噪声和比较规则，只运行冻结候选及冻结对照。不能看完各窗口分数后选最好窗口；后续若据确认结果再次优化，该窗口也变成开发证据，不能反复称独立确认。

可把固定后续窗口作为“未用于本轮offset2000选型、但与历史评测有交叉的确认”，明确限制；不能把它包装为完全未见盲测。若要严格覆盖全项目从未选型的要求，须补足617个潜在未见通道及缺失记录证据，或使用确实独立的新数据/实际线上评测。当前没有因此认定达标，目标仍未完成。
