# 评测数据划分审计（V227）

## 已确认的问题

纯神经训练器（含官方 payload 复训）固定使用 `deterministic_split_indices(..., seed=1176)` 的 train 部分。但旧 `evaluate_submission.py --seed S` 同时将 S 用于数据划分、SNR 和噪声。

数据共 100000 通道。严格逐样本复评每次取 test 前 2000 通道时，与固定训练划分的交集如下：

| 旧评测 seed | 与 train1176 交叉通道数 | 比例 |
|---:|---:|---:|
| 1176 | 0 | 0% |
| 1177 | 1614 | 80.7% |
| 1178 | 1587 | 79.35% |

因此，V224 的 68.065026 仍是可复现的**历史混合划分均分**，但不能称为三个严格留出集上的均分。1176 的 67.890964 不与上述训练划分交叉。此审计不把一次线上/本地接近视为泛化证明，也不修改历史数值。

## 修订协议

评测新增 `--split-seed 1176`，将数据划分固定，`--seed` 仅控制 SNR/噪声/随机 bits。新增 `--test-offset`，可从同一留出集选择从未用于历史候选复评的后续窗口。省略 split-seed 仍保留历史行为以便复现。

新协议预设 test_offset=2000、samples=2000，noise seeds=22701/22702/22703。先记录 V224 基准，再在完全相同输入上评测候选。这个窗口不用于梯度训练或训练中 checkpoint 选择；若今后反复据此选择架构，它也将成为开发集，不能再声称完全独立。

训练 checkpoint 仍由原 validation1176 选择，主干不根据训练内峰值晋级。逐 UE 结果额外保存 split_seed、noise_seed、test_offset；测试检查换噪声种子不改变通道，且与固定 train/validation 无交集。

统计对比按双用户通道成对重采样，保留两个用户之间的相关性。真实线上分数仍须用户提交后确认。
