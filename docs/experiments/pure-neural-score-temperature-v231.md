# V231：软评分温度单因素（完成，未采纳）

假设：V228说明硬/软排名更换本身没有明确净收益，但反向sigmoid温度一直固定0.5，仍可能与0阈值附近的判决边界不匹配。本次仅将温度0.5改为0.1，让梯度更集中于边界附近。

对照复用V230完整重跑的 `two_control_clean`（原并行two_control已中断，不纳入），候选从相同V227重新初始化两专家[0,1]，冻结Encoder、训练全部Tx/Rx。seed15240、batch100、Adam1e-5、12000步、每1000步验证2000通道，其他损失参数均不变。候选输出 `artifacts/pure_neural_v231/temperature01`，不与八专家混合成未经消融的组合。

GPU内存不足以容纳第三项训练，因此在当前训练释放资源后启动。温度降低也可能带来梯度方差或饱和，保留BCE0.05；不保证硬评分单调增长。选模型只用固定validation，严格留出集仅做配对audit；超过69的候选另外做未参与选择的新窗口复核。

资源调度：与完整两专家对照一致使用显存分配器上限0.4；两专家对照、温度、条件门控、伙伴SNR依次运行，不同时启动第三项GPU训练。只读的小批量诊断和逐样本评测在额外显存预算内执行。批量仍100、数值仍FP32，不改变单因素比较。

已完成12000步训练，最佳checkpoint为11000步，validation总分68.098107，低于同预算T0.5对照的68.174618。三噪声audit均分68.228263，较同预算对照低0.085636，配对95%区间[-0.116756,-0.056237]。结论：本配置净收益为负，不采纳。

日志口径：training_report中history的loss由evaluate函数使用BCE计算，并非训练的soft_score优化目标。在11000步，T0.1验证BCE为0.474864，对照为0.555197；BCE明显下降却没有带来更高的验证总分。正式训练实际使用的目标由loss_kind和温度等配置决定，不能据日志字段名误认成“仍用原始BCE训练”。
## 冻结模型的代理偏差诊断

另在split1176的validation前512个通道、seed25240、batch8上只做推理诊断，不更新权重、不使用新测试窗口。V227硬判决总分67.905809；全局软分在T0.5/T0.25/T0.1/T0.05时分别为67.492568/67.842461/67.917556/67.914535。每UE软分对硬分的平均绝对误差分别为0.467070/0.165808/0.100056/0.070479。

较低温度能减少代理偏差，但所有温度对应的硬判决仍是**同一份**67.905809；不能把仅改变代理计算得到的数字上升当成模型提分。该诊断的全局分位也不等同于训练时的minibatch平滑秩分位。只有重新训练后硬分改善才能采纳。原始结果见benchmarks/v227_surrogate_validation_diagnostic.json。
